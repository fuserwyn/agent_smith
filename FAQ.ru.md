## Коротко

### Что это?
Две вещи в одном репозитории:

1. **Agent Smith** — фреймворк код-агента, написанный с нуля (без smolagents, LangGraph, LlamaIndex, CrewAI,
   AutoGen). Модель рассуждает, пишет **Python-код, который вызывает инструменты**, код выполняется в
   **изолированной песочнице**, результат возвращается модели — и так до `final_answer(...)`.
   Агент решает задачи MBPP и чинит настоящие баги из SWE-bench Verified в Docker-контейнерах.
2. **Agent Smith Studio** — локальная веб-IDE вокруг агента: проводник, редактор Monaco, настоящий терминал,
   git, чат с агентом, где **каждый шаг виден, а каждое изменение можно посмотреть и откатить**, и
   визуализатор «Внутри агента», который показывает работу агента на схеме архитектуры — вживую.

### Чем это отличается от «ещё одного чата с LLM»?
- Агент **действует кодом**, а не JSON-вызовами: за один шаг он может прочитать файл, найти место, поправить
  и проверить — обычным Python.
- Всё, что делает агент, **прозрачно**: можно открыть любой шаг и увидеть мысль, точный код, каждую
  выполненную строку, каждый вызов инструмента и что вернула модель.
- **Безопасность заложена в архитектуру**, а не в промпт: код модели физически не может открыть сеть,
  прочитать ключи или выйти за пределы разрешённых папок.
- Работает **бесплатно**: по умолчанию бесплатные модели; платная модель доступна и явно помечена.

### Как попробовать за минуту?
```bash
git checkout agent-smith-studio
make studio-install                 # один раз
make studio P=~/путь/к/проекту      # откроет http://127.0.0.1:8790/?token=…
```
Ключи провайдеров — в `.env` самого Agent Smith (пример в `.env.example`). Для терминала нужен запущенный
Docker (или `--shell local`).

## Ядро агента

### Как устроен цикл агента?
`Thought → Code → Observation → … → final_answer`. Перед каждым запросом к модели проверяется **бюджет**
(итерации, входные и выходные токены, время): цикл никогда не делает запрос, который может нарушить лимит.
Если бюджет кончился, агент сдаёт лучший найденный вариант (для MBPP — последний код, прошедший тесты; для
SWE-bench — текущий патч) с честной пометкой `success=false` и причиной.

### Модель ответила не в том формате — что тогда?
Извлечение кода понимает пять форматов: блок ```` ```python ````, `<code>`, XML-вызовы, Hermes JSON и ReAct, —
и переводит их в Python. Если кода нет, модель получает явное сообщение с ожидаемым форматом. Если код
пришлось «починить», это тоже явно написано в наблюдении: ничего не происходит молча.

### Откуда агент знает, какие у него инструменты?
Инструменты **не захардкожены**: они берутся из MCP-сервера при подключении (`list_tools`), превращаются в
Python-функции с правильными аргументами, а из их схем автоматически генерируется инструкция для модели.
Поэтому агент работает с любым MCP-сервером, не только со своими. Поддерживаются stdio и streamable HTTP,
а также ресурсы и промпты MCP.

### Как агент не зацикливается?
Если модель присылает в точности тот же код, что недавно, он **не выполняется повторно**: модель получает
пометку `[LOOP]` с подсказкой, что делать дальше, а температура немного поднимается, чтобы сломать петлю.

### Насколько хорошо он решает задачи?
Из отчёта по SWE-bench Verified (все числа сгенерированы из реальных `solution.json`, проверенных moulinette):
`nvidia/nemotron-3.5-lightning-30b-a3b` — **3 из 3** задач, 146 с на все три, на бесплатном тарифе.
На MBPP — 5/5 на пробном экзамене у двух бесплатных моделей. Подробности, сравнение 5 моделей и абляция
промпта — в [BENCHMARK_REPORT.md](BENCHMARK_REPORT.md).

## Песочница и безопасность кода модели

### Что мешает коду модели сделать что-то плохое?
Код выполняется в **отдельном процессе** (`python -I -S`, пустое окружение, без ключей API) и проходит
несколько слоёв защиты:

| Слой | Что блокирует |
|---|---|
| Проверка AST | dunder-атрибуты (`__class__`, `__subclasses__`, `__globals__`…), атрибуты фреймов, импорты вне списка |
| Ограниченные builtins | нет `eval`, `exec`, `compile`, `globals`…; `getattr`/`setattr` отказывают для dunder-имён |
| Прокси модулей | импортированный модуль — только для чтения, без приватных имён и неразрешённых подмодулей |
| Audit hook | файлы вне разрешённых папок, сокеты (сеть), `subprocess`, `os.system/fork/kill`, `ctypes` — и его нельзя снять |
| Таймаут | на каждый блок кода; его нельзя «проглотить» через `except Exception`; на время вызова инструмента — пауза |
| Память | лимит процесса; хост следит за потреблением и перезапускает воркер |

Инструменты (чтение файлов, правки, тесты) живут **вне** песочницы, в MCP-сервере: воркер только просит их
вызвать через прокси.

### А SWE-bench?
Каждая задача — в своём Docker-контейнере `--network none`, с меткой; контейнер всегда удаляется, даже при
Ctrl+C или падении.

## Визуализатор («Внутри агента»)

### Что он показывает?
Схему архитектуры (задача → оркестратор → LLM → извлечение кода → песочница → MCP-клиент → MCP-сервер →
репозиторий), по которой «бегут» события прогона. Можно кликнуть любой блок и увидеть, что в него пришло и что
вышло на выбранном шаге; посмотреть код **построчно** (какая строка выполнилась, какие значения были);
увидеть вызовы инструментов, JSON-RPC, бюджет, harness тестов SWE-bench.

### Вживую?
Да. В студии схема **проигрывает события по мере поступления**, чуть отставая от агента; если отстала
сильно — ускоряется (до 8×). Пока прогон идёт, счётчик показывает «событие 9 из 10+ · идёт». Готовый прогон
открывается на финальном состоянии, ⏮ проигрывает его заново.

### Схема одна на всё?
Нет, она подстраивается: для MBPP — «песочница тестов», для SWE-bench — репозиторий в контейнере, для хода в
студии — ваш проект (в контейнере студии или локальная папка).

### А без студии?
`ui/index.html` работает и сам по себе: с записанными демо, с файлами трасс, с запуском реальных прогонов
кнопкой. Три языка (EN/RU/FR), светлая и тёмная тема, обзорный тур.

## Студия (мини-IDE)

### Что умеет как IDE?
- Проводник с живыми обновлениями файловой системы, вкладки, превью по одному клику.
- **Monaco** (редактор VS Code): подсветка, сохранение с защитой от конфликтов — если файл поменялся на диске,
  можно сравнить, перезаписать или перезагрузить.
- Быстрое открытие (⌘P) с нечётким поиском, поиск по файлам (⌘⇧F), статус и диффы git.
- **Настоящий терминал** (xterm.js) — несколько вкладок, переживает перезагрузку страницы.
- Палитра команд (⌘K), настройки, экран приветствия, EN/RU/FR, светлая и тёмная темы.
- Горячие клавиши работают даже когда фокус в терминале (как в VS Code), Cmd на macOS и Ctrl на остальных.

### Почему терминал в Docker?
По умолчанию каждая вкладка — `docker exec` в контейнер проекта: смонтирована только папка проекта,
процессы идут от вашего пользователя, остальная машина недоступна. Режим `--shell local` (обычная оболочка)
есть, но включается только явно и подсвечивается в строке состояния. Переменные с ключами и токенами
вырезаются из окружения любой оболочки.

## Агент в студии

### Ask и Agent — в чём разница?
- **Ask** — только чтение: инструменты, которые что-то меняют, агенту даже не показываются.
- **Agent** — правит файлы и запускает команды. Перед ходом студия делает **контрольную точку** в теневом
  git-репозитории (вне проекта — ваш `.git` не трогается). После хода видно, какие файлы изменились, у каждого
  есть дифф, и можно **откатить один файл или весь ход**.

### Можно остановить агента посреди работы?
Да, кнопка «Стоп» срабатывает до выполнения следующего блока кода, а если идёт запуск бенчмарка — останавливает
и его.

### Можно упомянуть файл?
`@` в поле ввода открывает поиск по файлам проекта.

## Запуск бенчмарков из чата

### Как запустить MBPP или SWE-bench «по кнопке»?
Командой в чате — без модели чата и без токенов:
```
/mbpp 2          /mbpp           /swe            /swe sympy__sympy-13480 <модель>
```
Запускается настоящий конвейер: задача из moulinette → `agent_mbpp` / `agent_swebench` → проверка. В чате
появляется карточка с этапами и вердиктом, а «Внутри агента» сам переключается на вложенного агента и
показывает его работу вживую. Наберите `/` — появится подсказка.

### А просто словами?
«Запусти один тест mbpp» тоже работает: у агента есть инструмент `run_agent_smith`, который он вызывает на
первом же шаге. Один такой прогон за ход; несуществующие номера задач отсекаются сразу с подсказкой ближайших.
Проверено на бесплатной модели: 17 секунд, 816 токенов.

## Агент собирает и запускает приложения

### Можно попросить «напиши сервер и запусти»?
Да. Например: *«Сделай простой сервер на FastAPI с маршрутами / и /health, в Docker, и запусти на порту 8123»*.
Агент пишет весь проект в `agent_code/apps/<имя>/` (код, Dockerfile, зависимости), вызывает `run_app` —
студия собирает образ и запускает контейнер на свободном (или указанном) порту `127.0.0.1`, ждёт, пока он
ответит, — после чего агент сам проверяет его через `call_app` и даёт ссылку. Обе такие просьбы проверены
вживую на бесплатной модели.

### Где смотреть, что с приложением?
Карточка в чате (ссылка, статус, логи, стоп), вкладка «Приложения» внизу (список и логи вживую), счётчик в
строке состояния.

### А это безопасно?
Контейнер слушает только локальный адрес, ограничен по памяти (512 МБ), процессору, числу процессов, без
capabilities и без повышения привилегий. `call_app` обращается только к приложениям, запущенным студией.
Остановка или закрытие студии удаляет контейнеры, при выходе удаляются и образы.

## Сгенерированный код (`agent_code/`)

### Где посмотреть код, который агент реально выполнял?
Каждый прогон — из терминала, на экзамене, в студии — сохраняет его в
`agent_code/runs/<бенчмарк>/<дата>_<задача>/step_NN.py`: мысль агента в шапке, **ровно тот код, что ушёл в
воркер**, и результат комментарием в конце, плюс `task.md` с промптом. Удобно изучать прогон, перезапустить шаг
руками или сравнить два прогона. Папка сама себя исключает из git (внутри `.gitignore` с `*`);
`AGENT_SMITH_CODE_DIR=off` отключает её.

## Безопасность студии

### Студия открывает доступ к моим файлам и терминалу — это не опасно?
Студия рассчитана на одного человека на своей машине и защищена как Jupyter, только строже:
- слушает **только loopback** (`127.0.0.1`);
- **токен сессии** в первой ссылке; `Referrer-Policy: no-referrer`, чтобы он не утёк;
- проверка `Host` (защита от DNS rebinding) и `Origin`, заголовок `X-Studio` на изменяющих запросах (CSRF);
- строгая **Content-Security-Policy**: только свои скрипты, никаких сторонних подключений; e2e-тест падает
  при любом нарушении CSP;
- **файловая тюрьма**: никаких `..`, абсолютных путей, выхода по симлинку; запись атомарная с сохранением прав;
- файлы вроде `.env` открываются только после явного подтверждения;
- **ключи никогда не попадают в браузер**, в оболочки или MCP-серверы; читается только `.env` самого
  Agent Smith, никогда — `.env` проекта.

## Модели и стоимость

### Как выбрать из сотен моделей?
**Вкладка OpenRouter**: баланс ключа и **Все модели** — каталог во всю ширину с поиском, видами (текст, картинки,
видео, аудио, эмбеддинги), фильтрами «что читает» (картинки, аудио, видео, PDF), ценами и контекстом.
Любую модель можно добавить в чат или назначить по умолчанию для картинок, видео, озвучки, голосового ввода, чтения
файлов или эмбеддингов. Выбор действует во всех проектах.

### Какая платная модель того стоит?
Измерено, а не угадано: одна и та же задача студии для 11 платных моделей (все решили, $0.002–0.08 за задачу) и три
настоящих бага SWE-bench для пяти из них (все 3/3). **Claude Haiku 5.5** — модель чата студии по умолчанию — решила
три бага SWE-bench за **$0.009** в сумме, GPT-6 Luna — за $0.007, Claude Sonnet 5.5 — за $0.13.

### Можно отправить файлы, фото, голос?
Да: файлы, фото, аудио, видео — скрепкой, перетаскиванием или вставкой. Модель, которая умеет такой тип, получает его
напрямую, иначе его сначала описывает дешёвая мультимодальная модель, так что это работает с любой моделью. Кнопка
микрофона записывает голос, модель расшифровывает, текст попадает в поле ввода — его можно поправить.

### Сколько это стоит?
Два мира. **Школьные бенчмарки и экзамен** (`agent_mbpp`, `agent_swebench`) работают на бесплатных тарифах (NVIDIA,
Google AI Studio, Groq, Cohere) с ротацией ключей, повторами и бесплатными запасными моделями — так требует задание.
**В чате студии** есть оба — две вкладки в выборе модели, а
кнопка у поля ввода всегда показывает, какой из них получит следующее сообщение:

- **Бесплатно** (зелёный) — бесплатные ключи Groq, Google AI Studio, NVIDIA и Cohere. Деньги не списываются; у каждого
  провайдера лимит запросов и токенов в минуту или в день. Выбор показывает эти лимиты, а после первого ответа — сколько
  осталось («осталось 990 запр. · 5.2k ток.»). При упоре в лимит ход ждёт несколько секунд или переходит на другую
  *бесплатную* модель — никогда на платную.
- **Платно** (янтарный) — ваш ключ OpenRouter, с ценой за 1M токенов и балансом. Выбранная модель делает весь ход (и
  запущенные из него прогоны), без перехода на бесплатные. Claude Haiku 5.5 (по умолчанию) решила три бага SWE-bench за
  $0.009; в заголовке хода видно, сколько он стоит.

Собственный бесплатный тариф OpenRouter (модели `:free`, роутеры за $0) не используется: OpenRouter в студии — это ваш
платный ключ.

Groq есть в обеих вкладках: **Groq · бесплатный ключ** (ваш бесплатный ключ Groq с его лимитами) и **Groq · через
OpenRouter** (то же быстрое железо Groq, оплата с ключа OpenRouter, без лимитов бесплатного тарифа). Во втором случае
модель закреплена за Groq (`openai/gpt-oss-120b@groq` → в OpenRouter `provider.only = ["groq"]`); через OpenRouter у Groq
есть gpt-oss-120b и gpt-oss-20b, qwen3.8-27b — нет.

### Какие модели можно выбрать?
Любые OpenAI-совместимые из `config/models.json` (свой список — через `AGENT_SMITH_MODELS_FILE`). В студии
модели без ключа видны, но выключены, а настройки подсказывают, какую переменную добавить.

## Качество

### Как это тестируется?
- **175 Python-тестов**: агентский цикл, извлечение, песочница, MCP, инструменты, API студии, файловая тюрьма,
  терминал, контрольные точки, сценарии, приложения (с фейковым Docker, который поднимает настоящий HTTP).
- **19 сценариев Playwright** гоняют настоящий сервер студии в браузере со скриптованной моделью: редактор,
  терминал, агент с диффом и откатом, «Внутри агента», палитра, CSP.
- Тесты с настоящим Docker — по флагу `STUDIO_DOCKER_TESTS=1`.
- CI на каждый push: Python, сборка веб-приложения, e2e. GitHub Actions закреплены по SHA, зависимости не
  моложе двух недель.

### Найденные баги исправлялись?
Да, и каждый — с тестом, который его воспроизводит: гонка «ход завершён раньше, чем посчитаны изменения»,
потеря последних событий в живой схеме, вылезающая за край колонка чата, кража фокуса терминалом, модель,
повторяющая пустой блок кода до лимита токенов, и другие — см. историю коммитов.

### Почему в README анимации, а не скриншоты?
GIF записываются автоматически: `make studio-gif` гоняет настоящую студию со скриптованной моделью и видимым
курсором, кадры собираются в GIF. После изменений интерфейса их можно перезаписать одной командой.

## Честно об ограничениях

- Студия локальная и однопользовательская; одновременно идёт один ход агента.
- Терминал по умолчанию и приложения требуют Docker.
- Образы SWE-bench — x86_64; на Apple Silicon они работают через эмуляцию и медленнее.
- Бесплатные тарифы имеют квоты (например, около 20 запросов в день у некоторых моделей Gemini).
- Маленькие модели иногда блуждают; студия ограничивает это бюджетом хода, стоп-последовательностями и
  правилами инструментов, но качество ответа всё равно зависит от модели.
